2  Which one to use for or purrr functions?

(Functionals in R: A simple introduction to map family functions in purrr)

When we start programming in R, one of the first things we learn is the for loop. A for loop allows us to repeat an operation multiple times.

For example, suppose we want to calculate the square of the numbers from 1 to 5, then we can write a simple for loop as follows:

result <- numeric(5)

for (i in 1:5) {
  result[i] <- i^2
}
result
[1]  1  4  9 16 25

There is another way to express the same idea using functionals.

2.1 What is a functional?

A functional is a function that takes another function as an input and uses that function to perform an operation.

Here is an example code to illustrate the idea of functionals.

apply_function <- function(x, f) {
  f(x)
}

The apply_function takes the function f as an input to the function. In other words f is a function passed as an argument. Now we can pass different functions to the apply_function as follows:

apply_function(5, sqrt)
[1] 2.236068

or

apply_function(5, abs)
[1] 5

or you can pass your own function as the input to the function as illustrated below.

power <- function(x, n) {
  x^n
}

apply_function_multi_input <- function(x, n, f) {
  f(x, n)
}

apply_function_multi_input(5, 2, power)
[1] 25

2.2 map family functions in the purrr package

The purrr package in the tidyverse provides many useful functionals. Some of the most commonly used illustrated below. These map() family functions are particularly useful when we want to apply the same operation repeatedly.

2.2.1 map(): apply a function repeatedly

Suppose we want to square the numbers from 1 to 5.

library(purrr)
map(1:5, function(x) {
  x^2
})
[[1]]
[1] 1

[[2]]
[1] 4

[[3]]
[1] 9

[[4]]
[1] 16

[[5]]
[1] 25

The important part is:

function(x) {
  x^2
}
function (x) 
{
    x^2
}

This is the function that we want to apply. The map() function takes each value in 1:5 and gives it to this function. The output is stored as a list.

Why does map() return a list?: A list is flexible because the result of each iteration does not necessarily have to be the same type.

Here is another example:

map(1:3, function(x) { data.frame( number = x, square = x^2 ) })
[[1]]
  number square
1      1      1

[[2]]
  number square
1      2      4

[[3]]
  number square
1      3      9

2.2.2 map_dbl(): when the result is numeric

If we know that every iteration produces a single numeric value, we can use map_dbl().

map_dbl(1:5, function(x) {
  x^2
})
[1]  1  4  9 16 25

The result is a numeric vector.

2.2.3 map_dfr(): when each iteration produces a data frame

Now the outputs from each iteration is stored in dataframe. Here, map_dfr() applies the function three times and then combines the resulting data frames by rows.

This is particularly useful when working with data analysis problems where every iteration generates a data frame with a single row that we want to combine into one larger data frame.

map_dfr(1:3, function(i) {
  data.frame(
    number = i,
    square = i^2
  )
})
  number square
1      1      1
2      2      4
3      3      9

2.2.4 Other map family functions

The map() family has different versions depending on the type of output you want:

2.3 Functionals and your own functions

We can define our own function and pass into map family functions as well.

For example,

square <- function(x) {
  x^2
}

Then:

map_dbl(1:5, square)
[1]  1  4  9 16 25

2.4 What is wrong with a for loop?

There is nothing wrong with a for loop. In fact, a for loop and a functional are often two different ways of expressing the same computational idea. Functionals are not simply a shorter replacement for for loops.

With a for loop, we tell R how to repeat an operation.

With a purrr functional, we tell R what operation we want, and purrr handles the repetition.

In simple terms:

for says: “Repeat this.”

purrr says: “Do this to each one.”

In otherwords, with purrr, we instead of repeatedly writing the mechanism for iteration, describe the operation you want to perform and let the functional handle the repetition.

For example

# for loop
result <- numeric(5)

for (i in 1:5) {
  result[i] <- i^2
}

With purrr:

map_dbl(1:5, function(x) x^2)
[1]  1  4  9 16 25

The purrr version focuses on the operation. It says, “square each number”. While map_dbl() takes care of the iteration.

2.5 Which one to use? purrr or for

There isn’t a rule that says always use for or always use purrr. Both are useful; the choice depends on the task and what makes the code clearest.

Use purrr when,

  • The operation is simple and repetitive

  • You want to apply a function to each element

  • You want concise, readable functional code

  • You want to control the output type

  • You are working with lists or nested data

  • You are already comfortable with tidyverse
